# Native Isaac CI integration

The adapter in `tools/isaac-modal` runs native task overlays using the existing Isaac image on Modal L40S. The workflow changes select this adapter only for tasks declaring `roboindustrial-image.json`; ordinary tasks keep their existing backend. Harbor is pinned to 0.21.0 and Modal to 1.5.4 for native tasks.

Task PRs execute host infrastructure from the trusted base revision. Until this infrastructure is merged, use the isolated-server harness to validate native task PRs.

1. Install the reviewed infrastructure from the trusted base revision on the CI host, separately from PR task content. Pin host Python >=3.12, `harbor[modal]==0.21.0` and `modal==1.5.4`; keep the adapter importable through an explicit PYTHONPATH. Never load host adapters, executable workflow helpers or Modal credentials from agent artifacts. Existing task-only PR overlays do not automatically install an infrastructure PR's code; land or explicitly approve the infrastructure change first.
2. Keep `validate_env="modal"` and GPU resource declarations for Isaac tasks. Resolve paired tasks from a reviewed registry, not an agent-selected `engine` field. A registered native task has separate environment/tests immutable overlay manifests, all source hashes, case IDs, and implemented status. Pending variants are reported as pending and excluded from trial execution.
3. In both matrix and non-Docker job-config branches, generate `environment.import_path="harbor_image_adapter:RoboIndustrialModalEnvironment"` plus `kwargs.modal_image_id`, `app_name` and bounded sandbox timeout. Use `harbor run -c job.json`. The existing `harbor run ... --env modal` path selects vanilla Modal and cannot use the opaque image ID. The corresponding MuJoCo task keeps its existing backend and image.
4. Apply that config selection consistently to `/validate` oracle and nop, `/run`, and any later `/cheat` path. `analyze` remains a separate observer job; it does not need Isaac GPU and must analyze the exact completed trial's source/version. CI must record the frozen PR head/task hash, adapter hash, SDK versions, image ID, actual sandbox IDs, candidate hash and engine/device evidence.
5. A separate verifier is a fresh GPU sandbox using the `/tests` immutable overlay. Agent phase is public-network; verifier phase is no-network, resolved by Harbor's existing network policy. The agent receives no Modal token and no oracle/test artifacts. Only `/app/output/submission.json` crosses into verification. The verifier launches native replay in a subprocess and writes reward only after exit code zero and a bound, complete result. Missing/aborted worker results must surface as infrastructure exceptions rather than reward-zero model failures.
6. The implemented `check_native_task.py` adds explicit static-check support for the custom `roboindustrial-image.json` definition: require image-ID adapter selection, two destination-specific overlays, exact file hashes, complete task metadata, agent/test separation, and no unsafe mount/secret kwargs. Do not add a fictitious Dockerfile merely to pass checks while running another image definition. The generated integration fixture is not publishable as a benchmark task or an algorithmic oracle.
7. Run the transport fixture first (empty submission must produce an ordinary format rejection with no infrastructure error), then a real native full-case candidate. After native port calibration, run oracle/nop/alternative and a valid-format physical counterexample in both engines. Exercise exit 134, time reset, missing case, altered candidate hash, altered source hash, forged metrics, and agent-side public-simulator edits. All malformed/failure cases must fail for the documented reason.
8. Freeze each of the 20 variants independently before actual model runs. Separate build/cold-start, GPU queue, agent, physics and verifier timing. An SDK shutdown abort, no GPU, broken asset cache or Modal service error cannot support “Astra cannot solve it”. Preserve all earlier MuJoCo and model successes.

Minimal job config shape (actual file generated by `build_smoke_task.py`):

```json
{
  "environment": {
    "import_path": "harbor_image_adapter:RoboIndustrialModalEnvironment",
    "delete": true,
    "kwargs": {
      "modal_image_id": "im-Nm8iLJCxhB14rzlvQjzhLD",
      "app_name": "roboindustrial-isaac",
      "sandbox_timeout_secs": 2400
    }
  },
  "agents": [{"name": "oracle"}],
  "tasks": [{"path": "<reviewed-native-task>"}],
  "n_attempts": 1,
  "n_concurrent_trials": 1
}
```

The agent and separate verifier each use their own task resource table. No business Modal volumes, asset download at verification time, existing business sandbox reuse, or agent-supplied metric imports are involved.

The implemented CI shim handles both the existing `harbor run -p ...` command shape and local JSON JobConfig. For a CLI run it substitutes only `--env` with the fixed import path; this was verified with the installed 0.21.0 `--print-config` command, not inferred from the factory. It preserves model/gateway flags. For JobConfig it replaces only the environment choice and refuses mixed native/ordinary batches. Native trial exceptions return exit 70; patched matrix steps and pipeline steps preserve this status rather than assigning a model reward of zero. Ordinary tasks retain their backend and installation behavior.

Real evidence so far: `tools/isaac-modal/evidence/harbor-empty-summary.json` records the actual 63.57-second, zero-exception separate-verifier rejection of an empty candidate. This is transport/schema evidence only. The physical no-op follow-up completed eight episodes and 24,000 steps in 175.41 seconds with reward 0 and no exception (`tools/isaac-modal/evidence/harbor-physical-negative-summary.json`). Calibrated per-task oracle/alternative/negative evidence remains a separate gate; none of the ten registry placeholders is promoted by this infrastructure patch.
